# Генетический алгоритм для раскроя полотен

Репозиторий содержит Jupyter/Colab-ноутбук с реализацией генетического алгоритма (ГА) для задачи раскроя полотен.  
Подробный разбор кейса на Хабре: https://habr.com/ru/articles/989646/](https://habr.com/ru/articles/989646/

---

## О чём задача

Есть лист материала фиксированной ширины (например, 2060 мм) и список заказов — прямоугольных изделий с известными длиной, шириной и количеством. Нужно разложить изделия по полотнам так, чтобы:

- суммарная ширина полос на полотне не превышала ширину полотна;
- суммарная ширина полос была не меньше технологического минимума (например, 1980 мм);
- на одном полотне было не больше двух уникальных длин изделий;
- не было пустых полотен;
- обрезь (отходы) была минимальной.

Задача NP-сложная: полный перебор невозможен, ручной подбор занимает часы и часто далёк от оптимума. ГА позволяет автоматизировать поиск за минуты.

---

## Идея решения

1. **Подготовка данных.**  
   Изделия каждого заказа объединяются в виртуальную «полосу»: длина = суммарная длина всех изделий заказа, ширина = ширина изделия.  
   Длинные заказы дробятся на подзаказы, близкие по длине к минимальному заказу. Это уменьшает разброс длин и снижает обрезь.  
   В примере 12 заказов превращаются в 44 полосы.

2. **Кодирование раскладки (бот).**  
   Один вариант раскладки — это список целых чисел длиной 44.  
   Индекс элемента = номер полосы, значение = индекс полотна (0…11), на которое эта полоса кладётся.  
   Пример: `[0, 2, 0, 3, 10, 3, 9, 4, 1, 5, ...]`  
   Такой список — это «бот» (особь, хромосома).

3. **Функция ошибки (function_error).**  
   Для каждого бота считается число — «плохость» раскладки. Чем меньше, тем лучше.  
   Ошибка складывается из:
   - **обрези по длине** — площадь, не закрытая полосами из-за разной длины;
   - **обрези по ширине** — площадь, не закрытая по ширине полотна;
   - **штрафов** за нарушение технологических ограничений (превышение ширины, недобор, >2 уникальных длин, пустое полотно).  
   Штрафы намеренно огромны (например, `1e16`), чтобы алгоритм быстро исключал недопустимые варианты.  
   Дополнительно используется параметр `lp` — суммируются ошибки не всех полотен, а только `lp` лучших. Это ускоряет поиск и позволяет фокусироваться на части раскладки.

4. **Генетический алгоритм.**  
   Цикл эволюции:
   - создаётся начальная популяция из `n` случайных ботов;
   - каждый бот оценивается `function_error`;
   - отбираются `nsurv` лучших (элита);
   - из элиты скрещиванием получаются новые боты (каждый ген случайно берётся от одного из двух родителей);
   - с вероятностью `mut` ген мутирует (заменяется случайным числом);
   - популяция дополняется до `n` и цикл повторяется `epohs` раз.

   Вероятность мутации можно снижать по эпохам (параметры `eph_change_mut` и `new_mut`), чтобы сначала исследовать пространство, а затем уточнять решение.

5. **Постобработка.**  
   Лучший бот декодируется в человекочитаемый вид: списки id подзаказов по полотнам, площади обрези, ошибки.  
   Хорошие полотна можно изъять из выборки и перезапустить ГА на оставшихся полосах — итеративный подход.

## Что есть в ноутбуке

- Подготовка данных: дробление заказов в полосы, формирование списка `polosa`.
- Реализация `function_error(bot)` с учётом всех штрафов.
- Полный цикл ГА: инициализация, оценка, отбор (`getSurvPopul`), скрещивание (`crossPointFrom2Parents`), мутация.
- Визуализация раскладок и графиков сходимости (средняя и лучшая ошибка по эпохам).
- Примеры хороших и плохих полотен с пояснениями.

## Параметры, которые стоит настраивать

| Параметр | Назначение | Рекомендации |
|----------|------------|--------------|
| `n` | Размер популяции | 50–200 |
| `nsurv` | Число выживших (элита) | 20–60% от `n` |
| `epohs` | Число эпох | 1000–5000 |
| `mut` | Вероятность мутации | 0.5 в начале, затем снижение |
| `eph_change_mut` | Эпохи смены мутации | например, `[500, 1000, 1500, 2000]` |
| `new_mut` | Новые значения `mut` | `[0.1, 0.05, 0.01, 0.005]` |
| `lp` | Число лучших полотен для оценки | 2–6 (зависит от задачи) |

`lp` — ключевой параметр стратегии. Если `lp` мало, алгоритм быстро находит несколько отличных полотен, но остальные могут остаться плохими. Если `lp` велико, поиск становится более равномерным, но медленным.

1. Установите зависимости: `numpy`, `matplotlib`, `random` (стандартная библиотека).
2. Откройте ноутбук в Jupyter или Colab.
3. Задайте свои данные: список заказов, ширину полотна, минимальную ширину, число полотен.
4. Настройте параметры ГА.
5. Запустите все ячейки. В конце вы получите лучшего бота, распределение полос по полотнам и визуализацию.

## Ограничения и допущения

- Модель не является полноценным 2D-раскроем: полосы укладываются вдоль длины, повороты не рассматриваются.
- Не учитываются керф (ширина реза), отступы, дефекты материала, направление волокон.
- Длина полотна не фиксирована — она определяется самой длинной полосой на полотне.
- Число полотен задаётся приблизительно и может пересчитываться при изъятии.
- Штрафы реализованы через большие числа, что может влиять на точность сравнения при суммировании с площадью обрези.
